## Postcards_lib.py
### Зависимости:
- **collections** (стандартная библиотека) — накопление вложенных счётчиков при группировке данных.
- **typing** (стандартная библиотека) — аннотация типов.
- **openpyxl** (сторонняя библиотека) — чтение исходного .xlsx-файла корпуса, создание и заполнение листов с результатами.

###  Магические значения:
- **SENDER_COLUMN** — буква столбца в исходном .xlsx-файле, содержащая имена отправителях.
- **RECIPIENT_COLUMN** — буква столбца в исходном .xlsx-файле, содержащая имена получателях.
- **POSTCARD_ID_COLUMN** — буква столбца в исходном .xlsx-файле, содержащая идентификационные номера открыток
- **HEADER_ROW** — номер строки, содержащая заголовки столбцов таблицы.
- **ILLEGIBLE_TAG** — тег, обозначающий невозможность разобрать имя отправителя или получателя открытки
- **MISSING_TAG** — тег, обозначающий отсутствие имя отправителя или получателя открытки

### Каталог функций:
- `compilate_data`
Читает данные из .xlsx-файла, связывает идентификационный номер открытки с отправителями и получателями, формируя два словаря.
- `compilate_grouped_counts`
Связывает отправителей и получателей (или другие опорные и связанные данные) по идентификационному номеру, считает кол-во найденных связей.
Работает с результатами функции `compilate_data`.
- `count_unsufficient_tags`
Считает кол-во тегов [ отсутствует ] и [ нрзб ] в переданном словаре вида {идентификационный номер открытки: имя}.
Работает с любым из результатов функции `compilate_data`.
- `table_compilate`
Cоставляет таблицу соответствий. Первый столбец - опорные данные, второй столбец - найденные соответствия, третий столбец - кол-во найденных соответствий.
Работает с результатом работы функции `compilate_grouped_counts`, `count_unsufficient_tags`

## main.py
### Зависимости:
- **openpyxl** (сторонняя библиотека) — создание и сохранение .xlsx-файла с результатами.
- **postcards_lib.py** (файл директории проекта) — основной функционал алгоритма.

## Поток данных
```
исходные данные (исходный .xlsx-файл)
   ↓
словарь "ID открытки" + "имя отправителя", словарь "ID открытки" + "имя получателя" (compilate_data)
   ↓
кол-во тегов [ нрзб ] и [ отсутствует ] (compilate_grouped_counts); словарь связей отправит. и получат., кол-во связей (count_insufficient_tags)
   ↓
.xlsx-файл с результирующими данными (table_compilate)
```

## Известные ограничения и технические решения:
| Ограничение/решение | Пояснение |
| ----------- | ----------- |
| Отсутствие алгоритма нечеткого поиска (разделение имен формата "Петр Иванович Н." и "Н. Петр Иванович")    | Требования реализовать алгоритм не присутствовало в техническом задании; это отдельный логический блок (определено в возможное направление развития).   |
| Отсутствие разделения имен, написанных через запятую (Петр, Маша)    | Позволяет установить стабильные связи совместного написания/получения писем при анализе результатов   |
| Cохранение значений [ нрзб ] и [ отсутствует ] в связанных данных    | Информация потенциальна значима при анализе результатов   |
| Сохранение тегов и разметки внутри имен    | Обеспечивает сохранение информации, указанной разметчиком   |

## Возможные направления развития
- объединение точных соответствий (например, в случае когда фамилия, имя и отчество написаны в разном порядке)
- выявление неточных соответствий (fuzzy match, см. строка №1 раздела *Известные ограничения и технические решения*)
- выявление результатов сопоставления для каждого отдельного отправителя / получателя (разделение имен, написанных через разделитель, напр. "," или "и")
- анализ метаданных об отправителе / получателе из текста открытки (должность, семейный статус, проч.)
- установление соответствий с датами первого и последнего получения / отправления открытки
